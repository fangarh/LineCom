# Человекочитаемый контекст

Эта папка - основная точка входа для чтения проектного контекста человеком.

Здесь хранятся договоренности, решения, заметки по бизнесу, обсуждения, открытые вопросы и краткие резюме важных материалов. Формат по умолчанию - Markdown.

## Правила

- Писать так, чтобы заметки можно было читать без знания внутренней структуры проекта.
- Фиксировать как важные решения, так и небольшие детали, если они могут пригодиться позже.
- Не смешивать исходные материалы с заметками: файлы, изображения, прайсы, каталоги и референсы лежат в `Assets`.
- Если мне нужен машинно-удобный формат, я могу дополнительно использовать JSON/YAML в служебных файлах `vault`, но человекочитаемые выводы должны попадать сюда.

## Текущая договоренность

- Проект: интернет-магазин для компании по продаже кабеля.
- `Assets` - хранилище сопутствующих материалов.
- `vault` - основная точка истины для контекста, решений и обсуждений.
- В `vault/Человекочитаемое` хранится версия контекста, удобная для чтения человеком.
- Технический стек зафиксирован в заметке `Технический стек.md`.
- Реализованная основа БД каталога зафиксирована в заметке `Catalog database foundation.md`.
- План маленьких итераций публичного API каталога зафиксирован в заметке `Public Catalog API iterations.md`.
- Контракт публичного read-only API каталога зафиксирован в заметке `Public Catalog API.md`.
- Дизайн этапа `Auth + Request Core` зафиксирован в заметке `Auth Request Core design.md`.
- План маленьких итераций этапа `Auth + Request Core` зафиксирован в заметке `Auth Request Core iterations.md`.
- План маленьких итераций frontend-среза `Frontend Auth + Request Flow` зафиксирован в заметке `Frontend Auth Request Flow iterations.md`.
- SEO/GEO - обязательное сквозное требование для всех продуктовых и технических решений.
- Приложения проекта хранятся в папке `apps`.
- Все артефакты моего тестирования и вспомогательных систем складываются в папку `temp`.
