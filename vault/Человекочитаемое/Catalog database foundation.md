# Catalog database foundation

## Назначение

Миграция `002_catalog_foundation.sql` задает первую релизную основу БД для каталога, характеристик и локальных файлов.

Она продолжает backend foundation и реализует часть структуры из заметок:

- `Структура данных релиза.md`;
- `Архитектура backend и БД.md`;
- `Продуктовая модель.md`.

## Реализованные таблицы

- `stored_files` - локальные файлы для изображений товаров, логотипов брендов, импорта, экспорта и временных файлов.
- `categories` - дерево категорий каталога.
- `brands` - бренды и производители.
- `products` - базовая карточка товара без публичной цены.
- `product_images` - изображения товара через `stored_files`.
- `category_attributes` - определения характеристик категории.
- `attribute_options` - справочник значений для `select`-характеристик.
- `attribute_value_aliases` - синонимы значений для Excel-импорта.
- `product_attribute_values` - типизированные значения характеристик товара.

## Заложенные ограничения

- Товар имеет одну основную категорию.
- `Product.slug`, `Category.slug`, `Brand.slug` уникальны.
- `sku` и `external_id` уникальны, если заполнены.
- Публичный статус наличия ограничен значениями `in_stock`, `on_order`, `check_availability`.
- Единица продажи ограничена значениями `coil`, `box`, `piece`, `pack`.
- Публичная цена в схему товара не добавлена.
- У товара может быть только одно главное изображение.
- Значение характеристики хранится только в одной типовой колонке.
- Тип характеристики проверяется триггером БД, а не только приложением.
- Значение характеристики можно записать только для характеристики основной категории товара.
- `attribute_option_id` должен ссылаться на значение той же характеристики.
- Файлы изображений товара и логотипов бренда проверяются по назначению `stored_files.purpose`.
- Дерево категорий защищено от циклов через PostgreSQL-триггер.
- Основную категорию товара нельзя изменить, если у товара уже есть значения характеристик.

## Что не входит в эту миграцию

- Пользователи, роли, организации и auth.
- Заявки и генерация номеров заявок.
- SEO-посадочные страницы.
- Excel import jobs и сохраненные mapping-конфигурации.
- Складской контур.

Эти блоки остаются отдельными следующими миграциями, потому что имеют собственные сценарии API, права доступа и транзакционные правила.

## Проверки

После добавления миграции выполнены:

```powershell
dotnet build .\LineCom.sln --no-restore -maxcpucount:1
dotnet test .\LineCom.sln --no-build -maxcpucount:1
```

Результат: сборка успешна, 5 тестов прошли.

Дополнительно добавлены SQL-text проверки и opt-in PostgreSQL-интеграционные тесты для миграций. Интеграционные тесты запускаются при наличии `LINECOM_TEST_CONNECTION_STRING` и могут пересоздавать схему `public` в тестовой БД.
