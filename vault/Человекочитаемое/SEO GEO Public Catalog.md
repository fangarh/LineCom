# SEO/GEO публичного каталога

Документ фиксирует контракт индексируемых публичных страниц LineCom, канонических URL, robots.txt и sitemap.xml для публичного каталога.

## Источник публичного origin

- Публичный origin сайта задается переменной окружения `LINECOM_PUBLIC_SITE_ORIGIN`.
- Значение используется как `metadataBase` на корневом уровне frontend-приложения.
- Относительные canonical path в metadata резолвятся через корневый `metadataBase` в абсолютные URL.

## Индексируемые страницы

В индекс попадают только публичные страницы:

- `/`
- `/catalog`
- `/contacts`
- `/delivery`
- `/catalog/{categorySlug}`
- `/products/{slug}`

## Закрытые внутренние поверхности

Внутренние поверхности не предназначены для индексации:

- `/admin/`
- `/account/`
- `/auth/`

Они закрываются двумя уровнями:

- через `robots.txt` с `Disallow` для `/admin/`, `/account/`, `/auth/`;
- через noindex metadata на route pages внутренних разделов, где такая metadata задана.

## Канонические URL

- Для статических публичных страниц canonical задается относительным путем и резолвится через root `metadataBase`.
- Для страниц категорий `/catalog/{categorySlug}` canonical path берется из публичного API категории.
- Для страниц товаров `/products/{slug}` canonical path строится из активного route slug, чтобы stale API canonical не мог вернуть старый `/catalog/products/...`.
- API-поля canonical path остаются источником правды для category pages.
- Старый `/about` является legacy URL и должен постоянно перенаправлять на `/contacts`.

## Sitemap

`sitemap.xml` строится из следующих источников:

- статические публичные страницы: `/`, `/catalog`, `/contacts`, `/delivery`;
- видимое дерево категорий публичного каталога;
- опубликованные публичные товары из public catalog API.

Если ветка загрузки категорий или товаров из API падает, sitemap route все равно возвращает доступные записи: статические страницы и успешно загруженные данные из другой ветки. Ошибка одной динамической ветки не должна обнулять весь sitemap.

Товары для sitemap загружаются с page size `60`, потому что это backend-valid размер страницы для public catalog API.

В Phase 4 sitemap остается единым `/sitemap.xml`, но загрузка товаров имеет явный release limit:

- не больше `10` страниц public catalog API;
- не больше `500` product URL в одном sitemap.

Если опубликованный каталог превышает этот предел, sitemap route возвращает валидный усеченный sitemap со статическими страницами, категориями и первыми product URL в сортировке `category`. Route не должен падать и не должен продолжать неограниченную API-нумерацию.

Когда каталогу потребуется покрытие больше этого release limit, следующий путь роста - сегментированные sitemap-файлы через Next.js `generateSitemaps`. До реализации сегментации `robots.txt` должен ссылаться только на текущий единый `/sitemap.xml`.

## Вне scope

В этот контракт не входят:

- SEO landing pages по фильтрам каталога;
- сегментированные sitemap-файлы в текущей Phase 4 реализации;
- генерация Open Graph изображений.
