<objective>
Implement the catalog import storage lifecycle so image files are staged privately, promoted only after DB commit, cleaned up by current-run manifest on failure, and physically cleaned after reset when selected by DB rows.

User story: As a release operator, I want catalog import apply/reset paths to leave DB and Local FileStorage in a recoverable, inspectable state so failed imports do not create unmanaged public files.

Purpose: Cover `STOR-04` and Phase 3 decisions D-01 through D-21 without adding web import/export, changing Local FileStorage target architecture, extending Phase 2 diagnostics endpoints, or broad destructive cleanup.
Output: Import core and WinForms behavior that implements staging/promotion/cleanup/reset outcome reporting. Regression tests are owned by Plan 03-02.
</objective>
