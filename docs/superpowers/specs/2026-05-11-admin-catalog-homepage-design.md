# Admin Catalog And Homepage Design

## Контекст

Этот документ фиксирует согласованный продуктовый и технический дизайн первого среза админки магазина LineCom для управления каталогом и карточками главной страницы.

Админка каталога является первичным рабочим контуром магазина. Импорт и экспорт остаются вспомогательными инструментами и не определяют модель данных, UX или правила публикации.

Проектные ограничения:

- backend использует PostgreSQL, Npgsql и Dapper;
- миграции выполняются SQL-скриптами через DbUp;
- Entity Framework не используется;
- файлы хранятся через Local FileStorage;
- SEO/GEO нужно учитывать при изменениях каталога, публичных URL, metadata и структуры главной;
- публичная цена и онлайн-оплата не входят в релизную модель.

## Цели

- Дать сотруднику магазина удобную админку для ручного создания и сопровождения каталога.
- Управлять товарами, категориями, характеристиками, брендами, изображениями и карточками на главной без импорта.
- Сохранить целостность данных, которые участвуют в публичном каталоге, заявках, фильтрах и SEO.
- Заменить автоматический выбор карточек главной ручными подборками из админки.
- Заложить расширяемость главной через фиксированные секции без превращения страницы в CMS.

## Не Входит В Срез

- Excel-импорт и экспорт как рабочие admin-сценарии.
- SEO-посадочные страницы по фильтрам.
- История изменений каталога и полноценный audit log.
- Встроенный crop/resize изображений.
- Общая медиатека.
- LLM-контроль дублей.
- Произвольные CMS-блоки главной.
- Складской учет, цены, скидки, онлайн-оплата.
- Дополнительные роли сверх `admin`, `seller`, `customer`.

## Роли И Доступ

Используются три роли:

- `customer` - покупатель: публичный каталог, заявки и личный кабинет.
- `seller` - продавец: рабочая админка магазина, включая заявки, каталог, товары, категории, характеристики, бренды, изображения и главную.
- `admin` - администратор: может все, включая возможности продавца и будущие системные действия.

В этом срезе `seller` и `admin` имеют одинаковый доступ к управлению каталогом и главной. Все мутации в админке требуют авторизацию и CSRF-защиту.

## Категории

Админка поддерживает полноценное управление деревом категорий:

- создание корневых и вложенных категорий;
- редактирование названия, slug, H1, описания, SEO-полей, активности и видимости в меню;
- сортировка внутри одного уровня;
- перемещение категории в другое место дерева;
- защита от циклов остается на уровне БД.

Перемещение категории не меняет основную категорию существующих товаров и не переносит товары между категориями. Перенос товара в другую категорию является отдельным действием, потому что меняется набор характеристик.

Физическое удаление категории разрешено только если у категории нет дочерних категорий, товаров и связей с карточками главной. Если категория уже используется, ее можно скрыть через `isActive = false`.

## Характеристики Категорий

Характеристики входят в первый срез админки.

Каждая категория имеет самостоятельный набор характеристик. Live-наследования от родительских категорий нет.

Поддерживается ручное действие `Унаследовать от родителя`:

- действие копирует недостающие характеристики родительской категории в текущую;
- копирование является разовым;
- после копирования характеристики редактируются независимо;
- повторное наследование не создает дубли по `code`;
- если в дочерней категории уже есть характеристика с тем же `code`, она не перезаписывается;
- для `select`-характеристик копируются опции;
- после операции админка показывает результат: сколько характеристик добавлено и сколько пропущено.

Редактор характеристик должен показывать:

- название;
- code;
- тип;
- единицу измерения;
- обязательность;
- фильтруемость;
- участие в сравнении;
- видимость в карточке товара;
- SEO-важность;
- использование в генерируемом названии;
- порядок;
- активность;
- количество товаров, где характеристика используется.

Безопасные правила:

- тип характеристики нельзя менять, если у нее уже есть значения у товаров;
- используемую характеристику нельзя физически удалить, ее можно деактивировать;
- используемую option у `select`-характеристики нельзя физически удалить, ее можно деактивировать;
- значения товара должны соответствовать типу характеристики;
- товар использует только характеристики своей основной категории.

## Товары

Админка поддерживает полноценное ручное создание и редактирование товаров.

Редактор товара строится как один экран с вкладками:

- `Основное`;
- `Характеристики`;
- `Изображения`;
- `SEO`;
- `Публикация`.

Во всех вкладках показывается блок `Готовность к публикации`, чтобы сотрудник видел, почему товар не может быть опубликован или не попадет на сайт.

### Основное

Вкладка содержит:

- название;
- slug;
- категорию;
- бренд;
- SKU;
- externalId;
- описание;
- краткое описание;
- статус наличия;
- единицу продажи;
- количество в единице продажи;
- порядок.

Смена категории после заполнения характеристик требует отдельного безопасного сценария, потому что текущие значения характеристик могут перестать соответствовать новой категории.

### Характеристики

Форма характеристик строится по выбранной категории товара.

Админка должна:

- показывать обязательные характеристики;
- использовать правильный control по типу характеристики;
- для `select` использовать справочник options;
- подсвечивать незаполненные обязательные поля;
- не давать опубликовать товар с некорректными значениями.

### Изображения

Медиатека не входит в первый срез.

Изображения загружаются прямо в карточке товара:

- поддерживается множественная загрузка файлов;
- поддерживается drag-and-drop;
- первое загруженное изображение может стать главным автоматически, если главного еще нет;
- главное изображение можно сменить вручную;
- порядок изображений можно менять;
- `alt` по умолчанию заполняется названием товара и редактируется;
- `title` необязателен;
- удаление изображения из товара отвязывает файл, но не обязано физически удалять его с диска;
- физическая очистка файлов остается отдельной служебной операцией;
- backend проверяет тип, размер и назначение файла `product_image`.

Crop/resize не входит в первый срез. Публичный frontend отображает изображения через существующие правила карточек.

### SEO

У товаров есть явные поля:

- `h1`;
- `seoTitle`;
- `seoDescription`.

Если поле пустое, публичный слой использует fallback:

- `h1` -> `name`;
- `seoTitle` -> `name`;
- `seoDescription` -> `shortDescription` или `description`, если значение подходит.

В БД не нужно принудительно записывать fallback-значения. Админка показывает итоговый SEO-preview и отмечает, какие значения будут использованы по умолчанию. Отсутствие ручного SEO не блокирует публикацию, но подсвечивается как рекомендация.

### Публикация И Активность

У товара есть два разных признака:

- `isActive`;
- `publishStatus`.

Смысл:

- `isActive = false` - товар отключен как рабочая сущность. Он не показывается публично, не попадает в подборки главной, не участвует в новых заявках и поиске, но остается в админке.
- `isActive = true`, `publishStatus = draft` - товар включен и редактируется, но не опубликован.
- `isActive = true`, `publishStatus = published` - товар может быть показан публично, если выполнены остальные условия видимости.

Публичная видимость товара:

```sql
products.is_active = true
and products.publish_status = 'published'
and categories.is_active = true
```

Отключенный товар остается доступен в старых заявках через snapshot-данные, но не может быть добавлен в новые заявки ни из публичного каталога, ни из админки.

Физическое удаление товара разрешено только если товар нигде не использован. Если товар уже попадал в заявки, его можно только отключить через `isActive = false`.

## Защита От Дублей

Механизм должен быть простым.

Жесткие дубли блокируют сохранение:

- `slug`;
- `sku`, если заполнен;
- `externalId`, если заполнен.

Похожие товары показываются как предупреждение, но не блокируют сохранение:

- похожее название в той же категории;
- похожее название с тем же брендом;
- похожий slug.

Для fuzzy-поиска используется PostgreSQL `pg_trgm`.

Админка показывает кандидатов в дубли:

- название;
- SKU;
- категорию;
- бренд;
- статус;
- ссылку открыть существующий товар.

Не добавляются:

- чекбокс подтверждения;
- audit log события `создано несмотря на предупреждение`;
- LLM-проверка дублей.

LLM-контроль дублей можно рассмотреть позже как отдельный инструмент качества каталога.

## Бренды

Бренды входят в первый срез как полноценный справочник.

Поля:

- `name`;
- `slug`;
- `description`;
- `seoTitle`;
- `seoDescription`;
- `logo`;
- `isActive`.

В карточке товара можно быстро создать бренд из поля `Бренд`:

- быстрый create требует только `name`;
- `slug` генерируется автоматически;
- `isActive = true` по умолчанию;
- описание, SEO и логотип можно заполнить позже.

Отсутствие SEO или логотипа у бренда не блокирует публикацию товара. Админка может показывать это как рекомендацию.

Если бренд неактивен, публичный товар может отображаться, но бренд не публикуется в публичном DTO товара.

Логотип бренда загружается прямо в карточке бренда через Local FileStorage, без медиатеки.

## Главная Страница

Главная уже существует. Этот срез не превращает ее в CMS.

Админка управляет только составом карточек в фиксированных секциях главной:

- какие товары или категории выбраны;
- в каком порядке;
- активен ли элемент;
- будет ли элемент реально показан публично.

Layout, тексты, визуальный стиль, SEO metadata и состав шаблонов главной остаются в коде frontend.

### Расширяемые Фиксированные Секции

Главная строится через справочник секций:

- `homepage_sections`;
- `homepage_section_items`.

Секции первого среза:

- `hero_products` - товары в верхнем блоке, лимит 3;
- `featured_products` - популярные позиции, лимит 8;
- `direction_categories` - категории в блоке направлений, лимит 4.

Будущие секции можно добавить как данные и frontend-шаблон, например `new_products` или `seasonal_products`.

Публичный frontend отображает только известные секции, для которых у него есть шаблон. Неизвестные `code` игнорируются.

Админка показывает:

- список секций;
- лимит секции;
- выбранные карточки;
- порядок;
- активность элемента;
- статус публичной видимости;
- быстрый поиск для добавления товара или категории;
- предпросмотр итогового публичного состава.

Если товар снят с публикации, отключен или находится в неактивной категории, публичная главная не показывает его даже при наличии записи в `homepage_section_items`. В админке такой элемент подсвечивается как проблемный.

## Модель Данных

Добавляется:

```sql
products.is_active boolean not null default true
```

Добавляются таблицы главной:

```text
homepage_sections
- id
- code
- title
- type
- item_limit
- sort_order
- is_active
- created_at
- updated_at
```

`type`:

- `product_list`;
- `category_list`.

```text
homepage_section_items
- id
- section_id
- product_id nullable
- category_id nullable
- sort_order
- is_active
- created_at
- updated_at
```

Ограничения:

- `homepage_sections.code` уникален;
- `homepage_sections.type` ограничен допустимыми значениями;
- для item должен быть заполнен ровно один target: `product_id` или `category_id`;
- тип item должен соответствовать типу секции;
- нельзя добавить один и тот же товар или категорию дважды в одну секцию;
- удаление товара или категории должно учитывать связи с `homepage_section_items`.

Для характеристик используются существующие таблицы:

- `category_attributes`;
- `attribute_options`;
- `attribute_value_aliases`;
- `product_attribute_values`.

Для файлов используются существующие:

- `stored_files`;
- `product_images`;
- связь логотипа бренда со `stored_files`.

Для поиска дублей включается и используется `pg_trgm`. Индексы под trigram-поиск добавляются на нормализуемые текстовые поля, которые реально участвуют в duplicate-candidates.

## API

Админские endpoints размещаются под `/api/admin`.

Каталог товаров:

- `GET /api/admin/catalog/products`;
- `POST /api/admin/catalog/products`;
- `GET /api/admin/catalog/products/{id}`;
- `PUT /api/admin/catalog/products/{id}`;
- `DELETE /api/admin/catalog/products/{id}`;
- `GET /api/admin/catalog/products/duplicate-candidates`.

Изображения товара:

- `POST /api/admin/catalog/products/{id}/images`;
- `PUT /api/admin/catalog/products/{id}/images/order`;
- `PUT /api/admin/catalog/products/{id}/images/{imageId}`;
- `PUT /api/admin/catalog/products/{id}/images/{imageId}/main`;
- `DELETE /api/admin/catalog/products/{id}/images/{imageId}`.

Категории:

- `GET /api/admin/catalog/categories`;
- `POST /api/admin/catalog/categories`;
- `GET /api/admin/catalog/categories/{id}`;
- `PUT /api/admin/catalog/categories/{id}`;
- `DELETE /api/admin/catalog/categories/{id}`;
- `PUT /api/admin/catalog/categories/{id}/move`;
- `PUT /api/admin/catalog/categories/{id}/sort`.

Характеристики категорий:

- `GET /api/admin/catalog/categories/{id}/attributes`;
- `POST /api/admin/catalog/categories/{id}/attributes`;
- `PUT /api/admin/catalog/categories/{id}/attributes/{attributeId}`;
- `DELETE /api/admin/catalog/categories/{id}/attributes/{attributeId}`;
- `POST /api/admin/catalog/categories/{id}/attributes/inherit-from-parent`;
- endpoints для options у `select`-характеристик.

Бренды:

- `GET /api/admin/catalog/brands`;
- `POST /api/admin/catalog/brands`;
- `GET /api/admin/catalog/brands/{id}`;
- `PUT /api/admin/catalog/brands/{id}`;
- `DELETE /api/admin/catalog/brands/{id}`.

Главная:

- `GET /api/admin/homepage/sections`;
- `PUT /api/admin/homepage/sections/{id}`;
- `POST /api/admin/homepage/sections/{id}/items`;
- `PUT /api/admin/homepage/sections/{id}/items/order`;
- `PUT /api/admin/homepage/sections/{id}/items/{itemId}`;
- `DELETE /api/admin/homepage/sections/{id}/items/{itemId}`.

Публичный API:

- публичный каталог фильтрует `products.is_active = true`;
- заявки проверяют `products.is_active = true`;
- публичная главная получает только элементы, которые проходят публичную видимость.

## Ошибки И Валидация

Используется текущий единый формат ошибок API.

Ошибки должны быть предметными и пригодными для UI:

- товар не найден;
- категория не найдена;
- бренд не найден;
- slug уже используется;
- SKU уже используется;
- externalId уже используется;
- товар нельзя удалить, потому что он используется в заявках;
- характеристику нельзя удалить, потому что она используется;
- тип характеристики нельзя изменить, потому что есть значения;
- изображение имеет недопустимый тип;
- изображение превышает допустимый размер;
- товар не готов к публикации;
- секция главной не найдена;
- item не соответствует типу секции.
- категорию нельзя удалить, потому что она используется.

Контроллеры не содержат SQL и предметную валидацию. Транзакционные операции выполняются в application/service-слое.

## Тестирование

Backend:

- миграционные SQL-проверки;
- unit/integration-тесты публичной видимости с `products.is_active`;
- тесты создания, обновления и удаления товара;
- тесты запрета удаления товара, который используется в заявках;
- тесты запрета удаления категории, у которой есть дочерние категории, товары или карточки главной;
- тесты duplicate-candidates;
- тесты безопасного редактирования характеристик;
- тесты наследования характеристик от родителя;
- тесты секций главной и фильтрации невидимых items;
- тесты загрузки изображений и проверки назначения файла.

Frontend:

- тесты API-клиентов админки;
- тесты списков товаров, категорий, брендов;
- тесты редактора товара с вкладками;
- тесты чеклиста готовности к публикации;
- тесты предупреждений о дублях;
- тесты управления карточками главной;
- browser QA основных сценариев.

## Основные Сценарии

### Создание Товара

1. Сотрудник открывает `Товары`.
2. Нажимает `Создать товар`.
3. Заполняет вкладку `Основное`.
4. Выбирает категорию.
5. Заполняет вкладку `Характеристики`, построенную по категории.
6. Загружает изображения.
7. Проверяет SEO-preview.
8. Открывает вкладку `Публикация`.
9. Исправляет ошибки из чеклиста.
10. Публикует товар.

### Управление Главной

1. Сотрудник открывает `Главная`.
2. Выбирает секцию.
3. Добавляет товар или категорию через поиск.
4. Меняет порядок.
5. Видит статус публичной видимости каждого item.
6. Сохраняет изменения.
7. Проверяет предпросмотр итогового публичного состава.

### Наследование Характеристик

1. Сотрудник открывает дочернюю категорию.
2. Переходит во вкладку `Характеристики`.
3. Нажимает `Унаследовать от родителя`.
