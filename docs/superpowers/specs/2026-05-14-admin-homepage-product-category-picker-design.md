# Admin Homepage Search And Product Category Picker Design

## Статус

Согласовано с пользователем 2026-05-14.

## Контекст

В папке `errors` зафиксированы две UX-проблемы админки:

- на `/admin/homepage` результаты поиска товара для секции главной страницы становятся нечитаемыми: название товара сжимается до вертикального текста по одной букве;
- на `/admin/catalog` при настройке товара категория выбирается плоским длинным списком, хотя в админке уже есть древовидный выбор категории при смене родительской категории.

Изученные компоненты:

- `apps/front/src/components/admin/homepage/admin-homepage-target-search.tsx`;
- `apps/front/src/styles/admin-homepage.css`;
- `apps/front/src/components/admin/catalog/admin-product-main-fields.tsx`;
- `apps/front/src/components/admin/catalog/admin-category-parent-picker.tsx`;
- `apps/front/src/components/admin/catalog/admin-category-tree-helpers.ts`.

## Цели

- Сделать карточки результатов поиска товара на главной читаемыми при длинных названиях, SKU, externalId и категориях.
- Заменить плоский выбор категории товара на дерево категорий.
- Разрешить выбор только конечных категорий, то есть категорий без дочерних категорий.
- Сохранить текущие backend-контракты: товар по-прежнему сохраняет `categoryId`, а наполнение главной по-прежнему добавляет ID найденного товара.

## Не входит

- Изменение публичных маршрутов каталога, metadata, sitemap, robots или canonical.
- Изменение модели данных категорий.
- Перенос товаров между категориями при изменении дерева.
- Массовые операции над товарами.
- Новые backend endpoints.

## Выбранный подход

### Поиск товара для главной

Карточка результата остается карточкой, но перестает зависеть от длины текста кнопки.

Правила:

- основной текстовый блок получает доступную ширину и не сжимается до нечитаемого состояния;
- кнопка действия показывает короткий текст `Добавить`;
- название, slug, SKU, externalId, категория и статус видимости переносятся внутри карточки;
- на узкой ширине кнопка может переходить под текст карточки;
- доступность сохраняется через явный `aria-label`, например `Добавить <название товара>`.

### Выбор категории товара

Плоский `select` в основных полях товара заменяется древовидным picker-компонентом, близким к существующему выбору родительской категории.

Правила:

- дерево строится из текущего списка `AdminCategoryListItem[]`;
- родительские категории отображаются для навигации и контекста, но не выбираются;
- конечные категории доступны для выбора;
- выбранная категория показывается в закрытом состоянии: название и slug;
- если у товара уже выбрана родительская категория, UI показывает ее как текущее значение, но требует выбрать конечную категорию перед успешным сохранением;
- frontend-валидация не заменяет backend-валидацию обязательного `categoryId`.

## Архитектура Frontend

Реализация должна быть узкой и переиспользовать существующие элементы:

- доработать `AdminCategoryParentPicker` или выделить из него общий `AdminCategoryTreePicker`;
- добавить режим выбора только leaf-узлов;
- заменить категорийный `select` в `AdminProductMainFields` на tree picker;
- поправить разметку и CSS `AdminHomepageTargetSearch`/`admin-homepage.css`, чтобы кнопка не ломала ширину карточки.

Если общий компонент получится заметно сложнее текущего parent-picker, предпочтительно выделить общий компонент с понятными props:

- `categories`;
- `value`;
- `label`;
- `buttonLabel`;
- `allowEmpty`;
- `isOptionDisabled` или `selectableMode`;
- `onChange`.

## Ошибки И Состояния

- Если список категорий пуст, picker показывает недоступное состояние и не дает выбрать категорию.
- Если в списке нет конечных категорий, picker показывает сообщение, что для товара нужна конечная категория.
- Если выбранная категория не найдена в текущем списке, закрытое состояние показывает, что категория недоступна, и пользователь должен выбрать актуальную конечную категорию.
- Родительские категории в дереве должны визуально отличаться от выбираемых конечных категорий.

## Тестирование

Frontend tests:

- карточка результата поиска товара отображает короткую кнопку `Добавить` и сохраняет доступное имя действия;
- длинное название товара не попадает в текст кнопки;
- tree picker товара не вызывает `onChange` при клике по родительской категории;
- tree picker товара вызывает `onChange` при клике по конечной категории;
- выбранная конечная категория отображается в закрытом состоянии;
- продуктовый payload по-прежнему отправляет выбранный `categoryId`.

Browser QA:

- `/admin/homepage`: поиск товара с длинным названием читаем, кнопка не сжимает карточку;
- `/admin/catalog`: в форме товара категории открываются деревом;
- родительская категория видна, но не выбирается;
- конечная категория выбирается и сохраняется;
- мобильная ширина не создает горизонтальный overflow.

## Проверка Технического Долга

Дизайн не оставляет намеренных временных решений:

- не добавляет второй несвязанный способ построения дерева категорий;
- не меняет backend без необходимости;
- не скрывает проблему длинных названий через обрезание всей полезной информации;
- не разрешает сохранять товар в родительскую категорию на уровне UI.
